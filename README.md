# Ulgamdagal AI Chat 1.0.3

Явные отказы до принятия сообщения переводят виджет в ручной повтор: исходные message, conversation_token, session_id, product_id и request_id сохраняются. Изменённый текст или другая страница товара — новый запрос. Автоматической повторной отправки нет. Ошибки отправки и enqueue без гарантированного отката сохраняют восстановление. Известные отказы WordPress до обработчика обрабатываются отдельно.

Конфликт ID останавливает автоматическую проверку и отправку. Потерянный токен требует явного нового диалога с новым session_id: подтверждение предупреждает о связи с оператором и риске повторения ранее принятого сообщения. Набранный текст сохраняется. При неоднозначном результате новый диалог не создаётся автоматически.

Диагностика REMOTE_ADDR и группы ограничения доступна только manage_options на странице настроек, без REST и без доверия к заголовкам. Общий IP не считается доказательством ошибки прокси.

Очередь оператора проверяет совпадение session_hash, role и content_hash, в том числе после гонки вставок event_id. Файл chat.js не использует optional chaining. Порог поддержки проверяется отдельно парсером ES2018; это не полная эмуляция старых браузеров.

Сервер 022 не изменяется. Проверки реальных PostgreSQL/API, конкурентных процессов и аварий требуют отдельного тестового окружения. Локальные подмены не подтверждают их прохождение. Nginx, очистка таблиц и белый список путей ссылок не входят в этот выпуск.

# Ulgamdagal AI Chat 1.0.2

Явные отказы до отправки текущего сообщения на API отмечаются request_not_sent. Виджет снимает ожидание только для известных локальных кодов с этой отметкой, сохраняет текст и не запускает проверку статуса. Обрыв связи, неизвестный 503 и ошибки проверки статуса сохраняют восстановление ответа.

Один выполняющийся запрос основного чата на нормализованный IP (IPv6 /64). Пользователи за общим NAT разделяют это ограничение. Пул по умолчанию — 4; можно задать целую константу ULGAMDAGAL_AI_CHAT_SLOTS в wp-config.php (1–16). Подбирать по ресурсам хостинга; увеличение не заменяет nginx-лимиты. Пулы оператора и восстановления отдельные. Нужны несколько именованных блокировок MySQL на соединение.

Тесты используют подменённые WordPress/БД и браузерное окружение. Нагрузочный тест реального PHP-FPM/MySQL не выполнялся. После обновления проверить чат, Telegram, отказ по лимиту и восстановление после обрыва.

# Ulgamdagal AI Chat 1.0.1

До четырёх одновременных основных запросов на установку WordPress; отдельные пулы оператора и восстановления сохранены. Минутный лимит и пауза 2 секунды обновляются под блокировкой MySQL. Защищённые паролем и неопубликованные товары/варианты исключены, в том числе при передаче ID и поиске по SKU. Требуется поддержка нескольких GET_LOCK на соединение. Это ограничивает длительные вызовы, но не заменяет ограничения nginx до запуска PHP.

Проверки локальные на подменённых WordPress/БД; реальная нагрузка PHP-FPM/MySQL не проверялась. После обновления проверить чат, оператора, восстановление и каталог на сайте.
